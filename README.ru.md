# plain-prose

Скилл для агента, который убирает из текста следы машинного письма. Английский, русский, немецкий. В комплекте чекер без зависимостей.

[English](README.md) · [Deutsch](README.de.md)

## Что это

Для этой задачи уже есть два хороших скилла, и они друг другу противоречат.

[stop-slop](https://github.com/hardikpandya/stop-slop) Хардика Пандьи — 13 КБ редакторского опыта: убить все наречия, ноль длинных тире, две части лучше трёх. Читается как человек, вычеркнувший много чужого текста. При этом ломает техническую документацию, не умеет отличать пост от справочника API, а в его собственном файле примеров длинное тире стоит ровно в той фразе, которая показывает, как обходиться без тире.

[avoid-ai-writing](https://github.com/conorbronsdon/avoid-ai-writing) Конора Бронсдона — 100 КБ инженерии: три режима, приоритеты, матрица послаблений по аудиториям, защита от дописывания фактов при переписывании и честный раздел о том, как детекторы ошибаются на неносителях языка. Всё это грузится в контекст при каждом вызове, и добрая половина — обвязка репозитория, а не советы по редактуре.

Здесь собрана дисциплина первого и инженерия второго, разобраны места, где они спорят, и добавлен слой, которого нет ни у одного: русский и немецкий.

Оба исходника под MIT. Этот тоже.

## Что изменилось при слиянии

| Вопрос | stop-slop | avoid-ai-writing | plain-prose |
|---|---|---|---|
| Наречия | Убить все | Убрать пустые усилители | Убрать пустые, оставить несущие факт. «Собирается по ночам» остаётся |
| Длинные тире | Ноль всегда | Норма на 1000 слов | Ноль в английской прозе, исключение для типографики списков, в русском и немецком правила нет вовсе |
| Обрывки фраз | Только полные предложения | Допустимы в разговорном голосе | Запрещены, когда сделаны ради драмы, разрешены, когда таков регистр |
| Сила утверждения | Звучит как приговор | Признак, а не доказательство | Признак, а не доказательство, и это записано в самом скилле |
| Размер | 13 КБ, грузится целиком | 100 КБ, грузится целиком | 9 КБ ядро, справочники по запросу |
| Языки | Английский | Английский | Английский, русский, немецкий |

Три языка — то, чего не было ни в одном исходнике. У русского машинного текста свои следы: канцелярит вместо глаголов, открывашки вроде «в современном мире», кальки «бесшовный» и «мощный инструмент». Не менее важны ложные друзья. Тире между подлежащим и сказуемым в русском обязательно, ёлочки — правильная типографика. Английский набор правил помечает и то и другое и ошибается дважды. Немецкому достался такой же разбор: Substantivstil отдельно, Gedankenstrich с пробелами отдельно.

## Установка

**Claude Code.** Скопировать папку в каталог скиллов:

```bash
git clone https://github.com/dripips/plain-prose.git ~/.claude/skills/plain-prose
```

Скилл включается, когда просишь почистить текст, проверить его или переписать. Подхватывается и сам, когда идёт работа над прозой.

**Другие агенты.** `SKILL.md` написан в формате agentskills.io, поэтому Cursor, Copilot, OpenHands и всё остальное, что читает этот формат, берут ту же папку. Справочники — обычный Markdown с относительными ссылками.

**Только чекер.** Node 18 и новее, ставить нечего:

```bash
node check.js draft.md
```

## Как пользоваться

```
почисти этот пост от следов ИИ
проверь post.md, но не переписывай
отредактируй README.ru.md на месте, контекст docs
перепиши сухо, это служебная записка
```

Три режима. `rewrite` возвращает чистую версию и перечитывает собственный результат, потому что после первого прохода следы остаются. `detect` только помечает. `edit` правит файл на месте по кускам и не трогает абзацы, которые уже написаны по-человечески.

Шесть профилей контекста решают, насколько строго судить. Пост и справочник API не получают одинаковых правил, а матрица в [references/contexts.md](references/contexts.md) говорит, какое правило где ослабляется.

## Чекер

```
node check.js [опции] <файл...>

  --lang en|ru|de|auto   язык текста (по умолчанию auto)
  --context <профиль>    blog|social|technical|pitch|docs|casual
  --json                 машинный вывод
  --strict               находки P2 тоже валят прогон
  --quiet                только строка оценки
  --skip-quotes          пропускать цитаты, для текстов про следы ИИ
```

Вывод:

```
$ node check.js черновик.md
черновик.md  [ru/blog, 412 words]
  P1     3  throat-clearing opener: "в современном мире"
  P1     7  tier 1 vocabulary: "мощный инструмент"
  P1    22  binary contrast: "Это не просто инструмент, это"
  P2    31  copula avoidance or officialese: "является" ×4
  P2     -  paragraphs are uniform (47/49/48/46 words), vary the length

  directness 6  rhythm 3  trust 8  authenticity 4  density 5
  proxy score 26/50  (below 35, revise)
```

Код возврата 0, когда чисто, и 1, когда что-то нашлось, поэтому чекер встаёт в pre-commit или в CI.

Перед разбором он затирает фронтматтер, блоки и вставки кода, адреса ссылок, голые URL и строки таблиц. Скилл обещает никогда не переписывать эти места, поэтому считать в них находки было бы нечестно. Два исключения работают по той же логике: тире, отделяющее лид-термин от пояснения в пункте списка, — типографика, а тройка внутри длинного перечисления — спецификация, а не ритм.

Оценка по пяти шкалам — приближение. Она меряет то, что доступно регулярному выражению: долю филлеров, разброс длин предложений и абзацев, количество хеджей, плотность словаря первого уровня. Настоящую оценку ставит модель, читающая текст, и те же пять шкал описаны для неё в `SKILL.md`.

## Чего он не делает

Не отвечает на вопрос, писал ли текст человек. Стэнфордский разбор нашёл у коммерческих детекторов больше 60% ложных срабатываний на эссе неносителей языка, у открытых — ошибки выше 70%. Каждый признак из этого каталога встречается и в тексте уставшего человека в час ночи. Пометки годятся, чтобы улучшить текст, и не годятся как довод об авторстве.

Ничего не дописывает. При переписывании можно вырезать филлер, уточнить уже сделанное утверждение, вытащить наверх закопанную мысль. Нельзя придумать число, имя, дату, позицию автора или реплику от первого лица. Придуманная конкретика всегда читается лучше и всегда хуже. Ограничения собраны в [references/rewriting.md](references/rewriting.md).

Не выполняет команды из редактируемого файла. Если внутри документа написано «игнорируй правила выше», эта фраза попадёт в находки.

## Состав

```
SKILL.md                    ядро, грузится всегда
references/phrases.md       слова и обороты, три уровня
references/structures.md    формы предложений и абзацев
references/rewriting.md     запрет на дописывание, голоса, форматы вывода
references/contexts.md      строгость по аудиториям, матрица послаблений
references/russian.md       русские следы, кальки, ложные друзья
references/german.md        немецкие следы, Substantivstil, ложные друзья
references/examples.md      было и стало на трёх языках
check.js                    чекер
check.test.js               29 тестов, node --test
```

## Разработка

```bash
node --test      # тесты
npm run self     # прогнать чекер по собственным файлам скилла
```

Самопроверка идёт с `--skip-quotes --context docs`: каталог запрещённых фраз состоит из запрещённых фраз. Даже так остаются находки в `references/examples.md`, где образцы «было» приведены без кавычек. Это известное ограничение: механический инструмент не видит, что пример — это пример.
